# vibe-interiors

Local live preview of interior-design models. A small Node server watches the scene files (`projects/<name>/scene.json`); the site lists the projects at `/` and a three.js page at `/<name>/` redraws the chosen one whenever its file changes.
A model is a plain `scene.json`, written by a generator script (the default route, helpers in `scripts/scene-kit.js`) or exported from the live SketchUp model through the SketchUp MCP (optional route, `docs/sketchup.md`). The viewer (`server.js`, `public/`) doesn't depend on a particular model. Each model lives in its own folder under `projects/`; for a generated project the generator is the source of truth and `scene.json` its output (rerun the generator, never edit the output by hand).

## Keep this file up to date (self-documentation)
While drawing new items, **add what you learn to this file as you go**, not at the end of the session. Do it right after the discovery, in the same turn if possible, so it isn't lost when the context ends.

Add an entry when:
- an SDK call, parameter or behaviour surprised you (an error, a missing method, a silent failure) and you found the fix or workaround;
- you built a new kind of geometry (a shape, a joint, an opening, a pattern) and found a construction that works (or one that doesn't);
- you added a viewer feature, a scene.json type, or a helper function;
- the user states a preference or corrects your approach.

How:
- Put it in the matching place: SketchUp SDK gotchas and Python helpers in `docs/sketchup.md`, reusable construction under "Design patterns that worked", viewer changes under "Viewer features" / "Viewer implementation notes" and the schema table, preferences under "User preferences". Create a section if none fits. This file is read at the start of every session: keep it short and put long reference material in `docs/`.
- Write the **rule plus the reason** in one or two lines, with a short code snippet only when it saves re-deriving something. Mark things you did not verify as unverified.
- If a helper is added or changed, update its code (`scripts/scene-kit.js`, or the block in `docs/sketchup.md`) so the next session can copy it as is. Update the "Ideas not done yet" list (remove what's done).
- If an older entry turns out wrong, fix or delete it, don't just add a contradicting one.

What not to write:
- Anything specific to the model being drawn (its name, rooms, dimensions, layout, colours, object names). Keep entries generic: describe the technique, not the object. Use neutral example names (`Unit_A`, `Slab_A`).
- Things already obvious from the code or from `git`-style history, or one-off state of the current session (URLs, save counts, temporary files).

Tell the user in one short line when you add something ("Added to CLAUDE.md: ..."), so they can veto it.

## Conventions and preferences
- **Reply in the user's language.** Personal preferences of the repo owner (language, tone) live in the untracked `CLAUDE.local.md`.
- **Language of the repo**: everything outside `projects/casa-costanza/` is in English (UI source strings, README, docs, code comments, console messages, test names, the `camera-test` project). The `casa-costanza` project data (its scripts, `scene.json`, names, labels, comments) stays Italian. Keep docs, comments and code in English. **UI text is never hard-coded**: it lives in `public/i18n.mjs` (`en` and `it`), used through `data-i18n` / `data-i18n-title` / `data-i18n-aria` / `data-i18n-html` attributes or `t('key')`; add every new key to BOTH dictionaries (`npm test` checks the keys, the `{params}` and that every key used exists). Only the interface is translated, never a project's data. The viewer still accepts `Rimosso` in item names (that data uses it) next to `Removed`.
- Measures: people think in metric (cm / m), but the SketchUp API is **inches only** and `scene.json` is in inches. Convert when quoting sizes (1 in = 2.54 cm); generators work in cm and the viewer shows cm by default.
- The project exists to give a free, local, auto-refreshing way to look at a model (why it exports from the live model: `docs/sketchup.md`).
- After a change, verify (a headless screenshot, `npm test`) before reporting, and say clearly what was verified and what was not (e.g. "checked in the preview, not reopened in SketchUp").
- Never save a `.skp` unless asked (see "Saves are limited" in `docs/sketchup.md`).
- The UI avoids the generic "AI look": the rules of github.com/leonxlnx/taste-skill (`redesign-skill`, `minimalist-skill`) were applied to the list and the viewer chrome: one accent colour, one gray family, tinted light shadows, real hover / press / focus states, no gradients, a font with character, non-Feather icons. Keep new UI inside those tokens (below).
- Tracked files are public-facing: no personal data (addresses, emails, phone numbers) and no hosting-provider names; deployment notes live in the untracked, git-ignored `CLAUDE.local.md`.
- Commit and push only when asked (the `check-and-publish` skill describes the flow); never rewrite history without an explicit request and a backup.

### Run / stop
```bash
cd <repo> && (nohup node server.js 4173 > server.log 2>&1 &)   # http://localhost:4173  (list)  ·  http://localhost:4173/casa-costanza/  (viewer)
pgrep -f "node server.js"            # is it running?
pkill -f "node server.js"            # stop (do this before restarting after editing server.js)
open http://localhost:4173
```
- Editing `public/viewer.html`, `public/index.html`, `public/plan.mjs` or `public/i18n.mjs` needs only a browser refresh (Cmd+R). Editing `server.js` needs a restart. A new `projects/<name>/scene.json` appears in the list on the next page load (no restart).
- The server stops when the Mac restarts. It watches `projects/` **recursively** (editors/writers replace files, so never single files), debounced 150 ms per project; only the viewers of the changed project are told to reload.
- Routes: `/` project list, `/projects.json`, `/<id>` (302 to `/<id>/`: the trailing slash is needed by the relative URLs), `/<id>/` viewer, `/<id>/scene.json`, `/<id>/events` (SSE), `/<id>/textures/*`, `/<id>/project.json`, `/<id>/thumb.jpg`, `/plan.mjs`, `/i18n.mjs`, `/fonts/*`, `/three/*` and `/vendor/*` (shared, as in `dist/`), `/favicon.ico` (204). `node server.js scene.json 4173` (old form) still starts: the file is ignored with a warning.
- The viewer lives one level down (`/<id>/`), so it uses RELATIVE URLs: per-project ones (`scene.json`, `events`, `textures/...`) and shared ones one level up (`../three/...`, `../vendor/...`, in the importmap and the OIDN weights path); the list uses `projects.json`, `<id>/`, `<id>/thumb.jpg`. The same files also work from a static host under any subpath. `npm run build` (`scripts/build-static.js`) writes `dist/` (`index.html` = list, `<id>/` = viewer + scene + textures + thumb.jpg per project, shared `three/` and `vendor/`) for a static host (hosted deployments run `npm run build` on every deploy and publish `dist/`, so `dist/` is git-ignored and NOT committed; deployment details are in the untracked `CLAUDE.local.md`; every runtime file the page imports must be copied by the build script, e.g. the path tracer bundles): sets `window.STATIC_BUILD` (no EventSource), copies the scene, textures and the three.js modules it needs, adds `noindex` headers and a `_headers` file with the cache rules. Keep new asset URLs in scenes relative (`textures/x.png`, not `/textures/x.png`).

## Workflow for every model change
Two routes. The first is the default and needs no SketchUp.

**A. Generator script (default).** The generator of a project is the script named in its `project.json` (`generator`), built on `scripts/scene-kit.js`.
1. Edit the numbers (a table at the top, every value tagged `measured` or `estimate`) or the module, in `projects/<name>/<generator>.js`.
2. Run it: `node projects/<name>/<generator>.js` (an optional `argv[2]` is the output path). The page reloads itself in about a second and keeps the orbit angle. The result exists only in the viewer, not in SketchUp: say so.
3. Verify: a headless screenshot ("Testing the viewer headlessly") and `node scripts/plan-report.mjs <name>` for the rooms and their interior sides; `npm test` before committing (it also checks that `scene.json` equals the generator's output).
4. `npm run thumbs` when the project card's picture should change. Commit and push only when asked.
For a new project use the `bootstrap-new-project` skill, for a real place `import-floor-plan`, for furniture `add-furniture`, to publish `check-and-publish`.

**The generator helpers live in `scripts/scene-kit.js`**: `createScene({ defaultOn })` returns `items` (the live array), `box`, `wall` (a wall with door / window openings: `wall(name, color, [x0, y0, x1, y1], height, [{from, to, sill, head}])`, emitting `_Seg`, `_Sill`, `_Lintel` pieces), `slab`, `tray`, `tube`, `rbox`, `mesh`/`quad`, `group`, `defGroup`, `light` (no default group: pass `g: '<group id>'`, and the group needs items or lights using it to get a checkbox), `camera` / `spawn` / `ceiling` (cm in, inches out) and `write(out, {camera, spawn, ceiling})`, which writes one item per line and omits absent keys. A new generator starts with `require('../../scripts/scene-kit').createScene(...)` and does not copy the helpers; `group()` appends `g` after the geometry key, so the key order differs from hand-written items (harmless). Curved lintels (arches) need a hand-made `mesh` item (quads between the arch polyline and the top edge, plus the intrados); the Plan sheet ignores them. Keep the scene small: boxes as `box`, curved things as parametric primitives (`tube`, `slab`, `tray`, `rbox`), never thousands of triangles.

**B. SketchUp MCP (optional).** Read `docs/sketchup.md` first: the live-model workflow (`build_model`, the exporter, `Write` the JSON to `projects/<name>/scene.json`, verify, save a `.skp` only when asked), the SDK facts and the Python helpers. If `mcp__sketchup__*` tools are not connected (it can fail silently: ToolSearch finds nothing), use route A.

## scene.json schema
```jsonc
{ "units": "inches",
  "camera": {"eye":[x,y,z], "target":[x,y,z], "up":[x,y,z], "fov":35},   // applied on FIRST load only; "up" is ignored (always Z up)
  "groups": [ {"id":"kitchen-v1", "label":"Kitchen v1", "cat":"Kitchen", "variant":"kitchen"} ],   // optional: switchable groups, see below
  "items": [ {"n":"/Group/Sub/Leaf", "c":[r,g,b,a], "g":"kitchen-v1", <exactly one geometry key>} ] }
```
Z is up (same as SketchUp). `n` is the group path (the tooltip shows the last two parts). `c` is the colour 0-255.

| key | meaning |
|---|---|
| `box: [x0,y0,z0,x1,y1,z1]` | axis-aligned box; optional `tex: {url, tile, face}` puts a repeating image on one face (see "Textures / patterns") |
| `faces: [ [[x,y,z],...], {"v":[outer], "h":[[hole],...]} ]` | generic mesh. Plain faces are fan-triangulated (**convex only**). Faces with holes are projected to 2D and triangulated |
| `tube: {p:[[x,y,z],...], r:[...], n}` | circular section along a path, per-station radius, smooth normals, flat end caps (pipes, faucets, handles, drains) |
| `slab: {o:[[x,y]...], h:[[[x,y]...],...], z:[z0,z1]}` | flat slab with polygon holes, extruded along +Z (worktops, floors with openings); optional item-level `tex: {url, tile}` repeats an image on the top/bottom caps in WORLD x,y (tile = inches per repeat), sides stay `c`: used for a wood floor |
| `tray: {o:[[x,y]...], z:[zFloor,zTop]}` | open-top tray, smooth inward walls + flat floor (sinks, basins, bowls with a rounded-rectangle plan) |
| `rbox: {b:[x0,y0,z0,x1,y1,z1], r, top, bot}` | rounded box: plan corner radius `r`, filleted top edge radius `top`, optional filleted bottom edge `bot` (default 0). Retro appliances, doors |

`loft` is emitted by the exporter if a prim has `type: "loft"`, but **the viewer has no loft handler** (use `rbox`, or add one to `geometryFor`).
Outlines are `EdgesGeometry` with a 20° threshold; materials are `MeshStandardMaterial`, double-sided, alpha < 255 makes them transparent.

## Viewer features (public/viewer.html)
- **Several projects on one site**: `/` lists every `projects/<id>/` that has a `scene.json` (cards: thumbnail, title, description, object count; the list comes from `projects.json`, built by `scripts/projects.js`), `/<id>/` is the viewer, so a project can be bookmarked (`/<id>/?view=Iso+2&g=...`; all the query params below still apply). The toolbar starts with a `← Projects` link (`../`). Optional `projects/<id>/project.json`: `{"title", "description", "thumbView": "<preset name>", "generator": "<script in the same folder>", "rooms": [{"name", "at": [x_cm, y_cm]}]}` (`rooms` names the rooms of the Plan sheet); a generator takes the output path as `argv[2]` (default: `scene.json` next to it), which lets `npm test` check that the committed `scene.json` is exactly what the generator writes today. Textures live in `projects/<id>/textures/` and scenes cite them relatively (`textures/x.png`).
- **Thumbnails**: `npm run build` screenshots each project (1200x750 JPEG q82, toolbar hidden, camera = the scene's saved one or `thumbView`) with `playwright-core` + Chrome headless (`CHROME_PATH`, else the usual macOS/Linux paths; same swiftshader flags as the test recipe) served from `dist/`, ~10 s for 2 projects. The screenshot hides the UI with a style tag listing the element ids (`#bar, #gbtn, #groups, #fphint, #tip, #labels` in `build-static.js`): **any new fixed overlay must be added there**, otherwise it shows in every thumbnail (the Groups button did once). No Chrome or `--no-thumbs` -> it copies the committed `projects/<id>/thumb.jpg` if there is one, else the list shows a letter placeholder. `npm run thumbs` (= `build-static.js --save-thumbs`) also writes `projects/<id>/thumb.jpg` and `thumb.json` (`{scene: <sha1 prefix of scene.json>}`) for committing (and the dev server shows it); when the build / `npm test` use a committed thumbnail they warn if the hash no longer matches the scene (stale: rerun `npm run thumbs`). Unverified: whether a hosted build environment can run Chrome; assume not and commit the thumbnails.
- **Environment of the dev server**: `PROJECTS_DIR=<folder>` serves another projects folder (the smoke test uses it for hostile / broken fixtures and for the reload-isolation check, so it never touches the real files), `HOST=0.0.0.0` opens it to the network (default 127.0.0.1); a missing projects folder only warns.
- **Language** (English / Italian): chosen by `?lang=it|en` (case-insensitive, region codes like `it-IT` work; if `localStorage` is blocked the switch keeps `?lang=` in the URL), else the saved choice (`localStorage` `lang`), else the browser language (Italian if it starts with `it`), else English; Node (tests, scripts) always gets English and never touches `localStorage` (Node 26 warns). The switch is an `EN | IT` row at the bottom of the gear menu (`#langrow`) and a pair of buttons on the project list; it saves the choice, drops any `?lang=` from the URL and reloads (view, camera and groups live in the URL, so they survive). Translated: the toolbar, tooltips and aria-labels, the camera view labels (the URL keeps the English names: `?view=Iso+2`), the Groups panel and the implicit "Removed elements" group / "Demolition" category, the status line, the first-person hint, the project list and the whole Plan sheet (also the `it-IT` / `en-GB` number and date formats). Not translated: project data (titles, descriptions, group labels and categories, item and room names), console messages, build / test output, docs.
- **Camera presets** (folded behind a camera-icon button `#camBtn`: click opens a vertical dropdown under the icon (outside the bar, which keeps its width), choosing a view, a key 1-9 or a click elsewhere folds it again; on phones the icon is hidden and the list lives in the `Views ▾` menu as a row inside the bar; buttons, keys 1-9): Saved (file camera), Iso, Iso 2, Front, Back, Left, Right, Top, Interior (66" eye height from near the min corner, fov 60). They are computed from the bounding box, so they follow the geometry. The active preset is highlighted with the accent colour.
- **The view survives a refresh through the URL**: a preset click writes `?view=<name>` (e.g. `?view=Iso+2`); any orbit/zoom writes `?cam=ex,ey,ez,tx,ty,tz,fov` (and clears `view`). On first load `?cam` wins, then `?view`, then the camera saved in `scene.json`. Scene reloads (file changes) never touch the camera. `history.replaceState` is used, so no history entries pile up. Open `http://localhost:4173/?view=Top` to start in a given view.
- **Zoom**: keys `+` / `−`, mouse wheel and pinch (OrbitControls); the on-screen `+`/`−` buttons were removed on request (dolly toward the orbit target; clamped 5…4000 in).
- **Keyboard fly**: `W/A/S/D` or arrow keys move camera+orbit target together on the floor plane (forward = view direction projected on XY), `Q`/`E` down/up, `Shift` = 3x faster (160 in/s base); the URL `?cam` is saved on key release.
- **PNG** button (key `P`): saves the image currently on screen (raster, AO, or path tracer canvas: the WebGPU one is `#rtgpu`, the others `renderer.domElement`) as `vibe-interiors-YYYYMMDD-HHMMSS.png`, at the canvas pixel size, with no toolbar, labels or tooltip. It is requested with a flag and executed at the end of the animation-loop callback, right after the frame is drawn (a WebGL canvas has no `preserveDrawingBuffer`, so `drawImage` only works in the same task); in raster/AO mode the dimension lines are hidden for the copy. Verified on raster and AO; the path-tracer branches are not tested.
- **Plan** (button after `First person`, desktop only; code in `public/plan.mjs`, imported by the viewer as `../plan.mjs`): a full-screen vector sheet with only the walls seen from above and the interior measures of each closed room, printable (`Print` = browser print / Save as PDF, `@page` size and the SVG's physical size follow the paper, A4 or A3, orientation and standard scale 1:20…1:500 chosen to fit) and downloadable (SVG, PNG at 200 dpi; fonts inside the downloads are system ones). Esc closes it and the viewer shortcuts stay quiet while it is open. How: walls = `box` / `slab` items with no group (the fixed shell) that cross the 100 cm cut (doors and windows show as gaps), glass (alpha < 255) skipped, the implicit group `removed` drawn dashed and only while it is on; rooms = closed empty regions of a 1 cm grid cut at (the lowest wall top that carries at least 15% of the wall area − 4 cm), where lintels close the openings (a column or chimney breast taller than the walls, or a short half-wall, does not move the cut), traced to a polygon, simplified (1.5 cm) and snapped (2.5 cm) to the exact wall coordinates; each side ≥ 30 cm is dimensioned (a rectangle only gets its width and depth) plus the net area; unnamed rooms under 0.8 m² are skipped. Names: `project.json` `"rooms": [{"name": "Bedroom", "at": [x, y]}]` (cm, a point inside the room; a point outside any closed room is warned about and ignored), otherwise "Room N" by area. Small rooms get smaller type and a one-line label. **Limits**: `faces` meshes (curved lintels, SketchUp-exported walls that are not boxes) are ignored, so such walls are missing and can leave rooms open (unverified on a scene exported from SketchUp); an open-plan area is one region (L shapes get every side); a vertical side dimension can touch the one-line label of a very low room.
- **Settings** (gear icon `#setBtn`): a dropdown under the gear (outside the bar, stays open while toggling, folds on a click elsewhere or when the camera dropdown opens) holding `Dims`, the unit button, `Click to measure` and `AO`; their keys (M, U, K, O) still work. The gear sits right next to the camera icon. `Render`, `PNG`, `Night`, `First person` and `Plan` are grouped together (`#actions`, in that order). On phones the gear is hidden and Dims / unit / Click to measure are rows of the `Views ▾` menu (AO stays desktop-only).
- **Dims** (key `M`): overall W/D/H of the whole model as dimension lines; **click an object** to dimension just that object (click again to clear); **hover** tooltip with name + size. **Unit button** (key `U`) cycles cm / in / m. **Click to measure** button (key `K`, on by default, kept in `localStorage`) turns click-to-dimension selection and the hover tooltip off/on together.
- **Night** button (key `N`, `?night=1`): daylight off (hemisphere 0.1, sun off, dark background), the scene's `lights` on, items with `"em": 1` glow (emissive). `lights: [{t:'spot', p:[x,y,z], d:[dx,dy,dz] (aim, default down), a: half-angle deg, pen: penumbra, c:[r,g,b], i: intensity, r: range (0 = none), sh: 1 = casts shadows, g: group id}]` in inches; a light follows its group like items. Decay is 1; ceiling lamps ~240, track lights ~300 worked. Each shadow caster uses one texture unit: keep them to ~12 (`sh: 1` only on the main light of each room, appliques without). Generators emit them with `kit.light({p:[cm], ...})` (cm -> inches); one wide spot per track, not one per head. Lights don't pass through walls only because of the shadows; without `sh` they leak into neighbouring rooms.
- **Mobile layout** (`@media (max-width: 820px)` or a coarse pointer up to 1100px): the top bar shows one compact row of the main actions (Night; Groups sits bottom-left as on desktop; AO, Render and First person are hidden on mobile: they need a GPU / keyboard) with 38 px touch targets; camera presets, Dims/unit fold behind a `Views ▾` button (`#bar.open`); the groups panel spans the full width. Desktop layout is unchanged. First person still needs a keyboard (no on-screen joystick yet).
- **AO** button (key `O`, `?ao=1`): screen-space ambient occlusion (three's GTAOPass through an EffectComposer, loaded on demand, 4x MSAA target so the edge lines stay clean). radius 16" (scene units are inches). Only on the raster view; the path tracer has it built in.
- **Render, WebGPU backend (default when `navigator.gpu` exists; `?rtgl=1` forces the WebGL one below)**: `three-gpu-pathtracer/webgpu` (wavefront kernels) on a SECOND canvas (`#rtgpu`, a `WebGPURenderer`) laid over the WebGL one, same `Scene` object, so the raster viewer, AO, picking and first person are untouched (a full WebGPURenderer port would have meant rewriting AO/GTAO and the GLSL denoiser for no gain). Denoising is the library's OIDN neural denoiser (`oidn-web`, weights `oidn-weights/rt_hdr_alb_nrm_small.tza`, 640 KB), the `Denoise` button toggles it; it runs when the image settles, so the first seconds are raw. Measured on the Mac GPU at 1700x1000@2x: ~1.5 samples/s over 2.5 MP (`?rpx=<MP>`), clean image after ~30 s, floor texture intact (the old GLSL filter washed it out). Tone mapping ACES, exposure 0.75 night / 0.8 day (set on `rtw.r`; the WebGL values 1.5 / 1.0 are far too bright here: same light units, WebGPU output is hotter). `import 'three/webgpu'`, `three/tsl`, `three-mesh-bvh/webgpu`, `three-gpu-pathtracer/webgpu`, `oidn-web` (use `dist/oidn.js`: `lib/` has extensionless imports the browser can't resolve), `@pmndrs/upscaler` (FSR, not wired yet) are in the importmap; `three-mesh-bvh` maps to its `src/` so there is one copy of the BVH classes; server `/vendor/` whitelist and `build-static.js` copy the `src/` trees. Headless test: Chrome with `--enable-unsafe-webgpu --use-angle=metal` works on the Mac (needs a secure context, i.e. localhost, not about:blank); `window.rtw` exposes `{pt, r, den}`, `rtw.pt.getSampleCountsAsync()` gives samples. Unverified: spot `radius` (soft shadows) is not read by the WebGPU kernels, the shadows look hard-edged.
- **Render, WebGL backend (fallback)** button (key `T`, `?rt=1`): progressive GPU path tracing with `three-gpu-pathtracer` 0.0.27 (`WebGLPathTracer`, deprecated upstream in favour of the WebGPU one; needs `three-mesh-bvh`), loaded on demand from `/vendor/...` (server route, whitelist of the two packages; `build-static.js` copies the bundles + `postprocessing/`, the shaders and `SimplexNoise`). Sky light = a `GradientEquirectTexture` environment (day bright, night 0.15), HemisphereLight hidden (not supported), `SpotLight`s switched to decay 2 with intensity x110. `setScene` is synchronous (the async build needs a BVH worker) so the page freezes a few seconds on every rebuild (reload, group toggle, night toggle). 4 bounces, a fixed pixel budget per sample (`rtScale()`: 0.8 MP, `?rpx=<MP>` to change; full screen on Retina is 10+ MP and ran at 0.27 samples/s vs 3 samples/s with the budget, measured on the Mac GPU at 1700x1000@2x, so the image is upscaled and a bit soft), ACES filmic tone mapping (exposure 1.0 day / 1.5 night, set on the renderer only while rendering), spots become `PhysicalSpotLight` with `radius` 3" (soft shadow edges; per-light override `rad`), restarts on camera move. **Denoiser** (inline in `viewer.html`, `Denoise` button next to Render, `?dn=0` starts off, `window.dn.phiK` = colour tolerance, default 6): the path tracer is set to `renderToCanvas = false`; each frame its float target goes through 2-5 passes of an edge-avoiding a-trous filter (5x5, steps 1,2,4,...) guided by a raster G-buffer (view-space normal + view depth, re-rendered only when the camera/scene changes, lines hidden, shadow maps off) and by the tone-compressed colour, with a firefly clamp on the first pass; then a final pass mixes it back towards the raw image (down to 25% filtered at 400+ samples, so textures come back) and does bilinear upscaling + ACES + output encoding (`#include <tonemapping_fragment>`). At ~50 samples the noise is gone while thin legs, cabinet edges and shades stay sharp (phiK 1 was far too timid, 8 cleanest); the cost is that repeating floor textures are washed out until enough samples accumulate. Before a first sample exists the raster view is drawn. Verified on the Mac GPU with Chrome `--use-angle=metal` (163 samples/48 s at 900x600); with swiftshader the shader compile never finishes, so don't test it headless in software. Edge lines are not drawn in this mode. Fireflies (white dots) and noise remain at low sample counts.
- **First person** button (key `F`, `Esc` exits; `?fp=1` starts in it): walk through the model at 66" eye height, fov 70. `W/A/S/D` or arrows move/strafe (80"/s, Shift 240"/s), `Q/E` turn left/right, click on the canvas to start mouse-look (pointer lock, no button held), click again to stop (pitch limited; Esc releases the lock). The white ceiling comes from `ceiling: {o:[[x,y]...], z:[z0,z1]}` in `scene.json` (inches; `kit.ceiling` reuses the floor polygon at the wall height): a flat slab outside `model`, visible only in FPV, no shadow casting, slightly emissive in daylight so it stays white; the path tracer rebuilds its scene when entering/leaving FPV. Spawn = `spawn: {p:[x,y], yaw}` in `scene.json` (inches, yaw degrees from +X ccw; `kit.spawn`, put it just inside the entrance door); without it, near the min corner looking at the centre. Collision = circle (6") against `box`/`rbox`/`slab` items with z between 8" and 62" (built with the meshes, so hidden groups, the "Removed elements" group included, do not block), axis-separated sliding; if the start is already inside something you can walk out. Exiting restores the orbit camera. **Pitfall**: `OrbitControls.update()` still re-aims the camera at its target when `enabled=false`, so the render loop skips it in FPV. `window.fpState()` exposes `{x,y,yaw,pitch}` for headless tests (load takes ~8 s under swiftshader, wait for the status line before reading it).
- **Groups** button (key `G`, shown only when the scene has groups; fixed at the bottom-left, outside the top bar, and its panel opens right above it): a panel (desktop: fixed 380 px wide (less on a narrow window), long labels wrap under the text; phones: full width) with one checkbox per group, listed by category; **everything is off by default**, except groups with `"on": true` in `scene.json` `groups` (`createScene({ defaultOn })` in a generator), applied on first load only when the URL has no `?g`. An item with `"g": "id"` (or a list of ids) is drawn only when one of its groups is on; items without `g` are always drawn. Groups sharing the same `variant` are mutually exclusive (turning one on turns the other off), others are independent. "All on" picks the first group of each variant set. The enabled ids live in the URL (`?g=id1,id2`), so a refresh keeps them. Ids used by items but missing from `groups` appear under "Other". Each category title is a collapsible header (`›` closed / `v` open, click to toggle; closed headers show how many of their groups are on; the state is kept in `localStorage`, not in the URL). Off groups aren't built (hover, dims and click ignore them); the status line still counts all items.
- **Removed elements** (a group, no dedicated button or key any more): on load the viewer gives every item whose name contains `Rimosso` or `Removed` (walls to be demolished) and that has no `g` the implicit group `removed` ("Removed elements", category "Demolition"), added to `groups` if the scene does not define it. It is off by default ("after the works" state), shown by ticking it (`?g=removed` bookmarks it), and **left out of "All on"** (`skipAll`: the demolished walls would overlap the new furniture). Name demolition candidates `..._Removed` (new projects; `..._Rimosso` also works) and colour them differently in the scene; an item with its own `g` follows that group instead. The old `Rimossi` button / key `R` is gone (`Rimosso` is also accepted in names because the casa-costanza data uses it).
- Live status dot (green = SSE connected) + object count + last-reload time.
- Reloads rebuild the meshes but keep the orbit camera, the selection and the dimensions.

## Design patterns that worked (generator route)
- **Validating a model against the user's photos** (listing photos, wide-angle): (1) say where the camera is and which way it looks, then check handedness (looking south, left = east; looking west, left = south), a left/right slip once put a radiator on the wrong side of a door; (2) get px/cm from something the user measured in the same plane (a door luce, a niche width) and don't compare objects at different depths; (3) wide-angle views at different depths mislead, so treat small mismatches (~15%) as perspective and only change the model for clear contradictions (a missing feature, an element on the wrong wall); (4) a render from the same viewpoint (`?cam=ex,ey,ez,tx,ty,tz,fov` in inches) beats guessing;
- **Furniture variants as switchable groups** (script-generated models): one module per variant (e.g. `projects/<name>/kitchen-v1.js`, exporting `function ({ box, tube, rbox, group, n })`), required by the generator, with everything drawn inside `group('<id>', () => {...})` and declared with `defGroup(id, label, cat, 'variant')` (same `variant` = mutually exclusive). Design the variant for the *final* state of the walls and say so (it overlaps items named `Removed` / `Rimosso` when the "Removed elements" group is on). Useful primitives: `rbox` for worktops/shades (rounded), `tube(..., seg)` with `seg` 14-20 for round stools/jars/globes, thin boxes for slats and door fronts, handles as 0.8 cm tubes 1-2 cm off the face.
- **Generator tricks that paid off while furnishing**: (1) pieces that need a rotation (45° corner sink, rotated appliance) = `slab` polygons in plan (the viewer has no rotation; `slab` takes any CCW polygon + a z range), tubes just rotate their path; (2) to swap or move whole blocks of a module wrap its helpers with a y-shift (`let SHY`, `box = (...) => _box(..y0+SHY..)`) instead of renumbering coordinates; (3) after each furniture change run a numeric check from `scene.json` (item bounding boxes vs. walls and vs. each other, clear space in front of doors/appliances, widths of aisles) and render from the user's viewpoint (`?g=<group>&cam=...`): it caught a fridge whose door could not open and overlaps of 1 cm; (4) keep removed-but-maybe-later pieces in their own module (e.g. `appliances-extra.js`) with re-enable instructions in the header.
- Openings in thick walls with boxes (`kit.wall` does segments + lintel + sill), plus a 4 cm "false jamb" (two posts + head) when the user wants doors drawn without leaves; niches = a full-height wall box behind (e.g. 7 cm left of the wall) + side/lintel boxes, window set back inside it; sloped walls get split into several `slab` polygons (a recess = a slice with its inner edge offset).
- **Sanitary fixtures in the script generator**: furnish *on top of the existing plumbing connections* (their own groups): put each fixture's centre on its connection's coordinate and check the footprint covers the floor drain. `kit.slab(n,c,poly,z0,z1,holes)` + `kit.tray(n,c,poly,zFloor,zTop)` give recessed basins/bowls (rounded-rect `rr()` polygons, tray inset 0.2 cm from the hole, thick ceramic top so the tray floor stays above the slab bottom). A fixture whose centre is < half its width from a wall needs a recess (window niche) or a narrower rear body, check with a numeric box-overlap script against the wall boxes. Shower = low tray + thin transparent boxes (alpha 70) + chrome rail; washing machine = `rbox` + 2-station `tube` along X for the porthole.
- **Fixtures against a sloped (oblique) wall**: the viewer can't rotate boxes, so build the fixture in a local frame (u along the wall, v from the wall) and map the rounded-rect polygons to world x,y (`slab` + `tray`; the map flips handedness, so reverse the point list to stay CCW). Put the local origin so the existing drain lies on the fixture's centre line, then push the fixture 0.8 cm off the wall and verify with `max(y - L(x))` over the polygon vertices (<= 0). Shared decor helpers (plant, pot, print) can live in one module.
- **New variant = transplant a block from another variant** (e.g. a `kitchen-v6.js` = v2 + the L leg of v4): copy the base module, rename the group id / `P` prefix / function, replace only the block that changes (delete the item it supersedes, e.g. the old fridge), paste the other variant's block with the same coordinates, register `defGroup` + `require` in the generator. Keep the base's colours for the pasted cabinets (swap `WH` for the base's `SG`), and check clearances numerically (door swing vs. neighbouring piece) plus a top view.
- **Reusing a furniture module in another room / orientation**: call the existing module with wrapped helpers instead of copying it: `box/rbox/tube` mapped through `X' = a - X, Y' = b - Y` (a 180° turn keeps handedness; mirrors flip it), min/max re-sorted for `box` and `rbox.b`, `group: (id, fn) => fn()` so everything lands in the caller's group, and rename the item prefix. Shelving in a niche of an oblique wall: shelves as parallelogram `slab`s (vertical sides flush with the niche sides, front/back parallel to the wall), books as axis-aligned boxes whose back follows `L(x)` (gap < 1 cm per book), large objects (baskets, towels, flat books) as `slab`s in the local (u along wall, v into room) frame.
- **Walk-in closet behind a free-standing partition** (a variant of a wardrobe set): a full-height box wall as long as the bed, TV on the bed side, open-front wardrobe modules on the far wall, ends left open as passages; a partition shadows the room's ceiling light, so give the closet its own `light({... g:'<group id>'})` (the `light` helper is passed into the module from the generator). Parametrize the partition's face position and check aisle (module front to partition) vs. gap at the bed foot.
- **Chairs around a table, any orientation**: build one chair facing +y at the origin and map it to the world with `W(x, y)` for 0 / 90 / 180 / 270 degrees (a box or `rbox`: transform two corners and re-sort min / max so it stays axis-aligned; a `tube`: map its points); an oval or round top = a `slab` polygon of ~48 points; a square cushion turned 45 degrees = a `slab` diamond. Seats start 26 cm from the table axis, so keep pedestal legs shorter than that (y +-24) or they poke through the seats; check it with a numeric overlap script like the one in "Generator tricks".
- **Wall decor helpers on a wall along the other axis**: the shared decor helpers (frames, pots, plants) assume a wall along x (x = along the wall, y = distance from it). For a wall at x = XE pass them an adapter instead of rewriting them: `bE = (nm, c, xa, ya, za, xb, yb, zb) => box(nm, c, XE - yb, xa, za, XE - ya, xb, zb)` and `tE = (nm, c, p, r, seg) => tube(nm, c, p.map(([x, y, z]) => [XE - y, x, z]), r, seg)`, then give your own objects local coordinates the same way (the world y along the wall, the depth from the wall).
- **Cheap decor in the script generator**: potted plant = conical 2-station `tube` pot + ~8 leaf `tube`s with 3 stations and radii `[0.3, 2.6, 0.2]` fanned out (keep horizontal reach small near walls/glass); wall print = 4 frame bars + mat + background boxes + a 2-station `tube` along the wall normal as a disc, with a `yw`/direction parameter so it works on any wall; folded towel = thin box 3-4 cm in front of a radiator. Numeric overlap checks flag false positives for tubes along the wall normal (the radius is added to every axis).
- **Rounded door pair**: upper door `top` fillet, lower door `bot` fillet (`rbox` with `bot`), both with the same plan radius; the cabinet behind is a plain `rbox` with a small radius; leave the doors overlapping the cabinet by ~0.4" so no seam shows from the side.
- **Lights belonging to a furniture module** (a pendant over a counter): pass `light` from the generator into the module and call `light({p:[x,y,z], i, sh, g:'<group id>'})` just below the lamp (z under the shade, never inside its closed mesh or the shade shadows it), then flag the shade `em = 1` in the generator next to the other glowing items. A lamp without a `light` entry only looks like one; it gives no light in Night / Render.

### Textures in scenes
**Viewer side:** the full-resolution tile goes in `projects/<project>/textures/<name>.png` (served at `/<project>/textures/<name>.png`; build the seamless mirrored version with PIL too). In `scene.json` add `"tex": {"url":"textures/x.png","tile":36,"face":"-y"}` to a **`box`** item: that face gets the texture repeated every `tile` inches, the other faces use `c` as plain colour (set `c` to the edge colour). Boxes (one face) and slabs (top/bottom caps, world x,y) support `tex`. Generators set it right after the `box` / `slab` call: `items[items.length - 1].tex = { url: 'textures/x.png', tile: 36 };`. The SketchUp exporter doesn't emit `tex`: after exporting, add it with the node patch below (match on the leaf name), and keep `session_state["tex"][leaf] = {...}` as the record of what was textured (the SketchUp side is in `docs/sketchup.md`).
```js
for (const i of s.items) if (i.n.endsWith('/Door_Front')) { i.c = [edge r,g,b,255]; i.tex = {url:'textures/x.png', tile:36, face:'-y'}; }
```

## Viewer implementation notes / pitfalls found
- **Design tokens** (`:root` in `public/viewer.html` and `public/index.html`, same values): `--ink #1c2330`, `--muted #667085`, `--line*` (cool gray family), `--bg #f4f5f7` (also the WebGL clear colour: change both together), `--accent #b5532a` (the ONE accent: every on / active / open state, the dimension lines and labels, focus rings; the 3D dimension line uses `0xb5532a`), `--shadow` (tinted, low opacity). Night is the only other fill (`--ink`). Don't add a second accent, blue/purple gradients, glass, heavy black shadows or Inter. Buttons have hover (`#f1f3f6`), press (`scale(.97)`), `:focus-visible` ring and 150 ms transitions: new buttons get them from the generic `button` rules. Numbers use tabular figures; dimension labels use Geist Mono. Icons: Phosphor (regular, `fill=currentColor`, viewBox 256), not Feather/Lucide.
- **Fonts**: Geist + Geist Mono, self-hosted from `@fontsource-variable/*` (SIL OFL 1.1): `/fonts/geist.woff2` and `/fonts/geist-mono.woff2` (`FONTS` map in `scripts/projects.js`, served by `server.js`, copied by the build to `dist/fonts/`); the viewer references `../fonts/...`, the list `fonts/...`. The thumbnail screenshots hide the bar, so they are font-independent.
- **`held` also holds `'shift'`** (the speed modifier): every loop over `held` in the orbit-mode fly code must skip keys that are not in `MOVE` (it threw a TypeError every frame once). **`refreshDims()` resets the emissive colour of every mesh** (selection highlight): the "em" materials are restored from `emissiveMats`, otherwise the night glow vanishes after the first load. Toggle buttons get `aria-pressed` from a MutationObserver on their class (list in the script: add new toggles there).
- **Never name a local variable `t` in a file that imports the translation function** `t` (`public/index.html`, `viewer.html`, `plan.mjs`): the project list broke once (`t is not a function`) because of a `const t = ...` in a loop.
- `slab` **requires `h`** (use `h: []` when there are no holes): without it `slabGeometry` throws and the whole scene silently stays on "waiting for valid scene.json…". `load()` now logs the real exception with `console.error('scene load failed:', e)`, so run the headless script and read the console first.
- Scene is Z-up: `THREE.Object3D.DEFAULT_UP.set(0,0,1)` and `camera.up.set(0,0,1)`. **Never set `camera.up` from the file** (SketchUp's saved up-vector has roll; OrbitControls then tilts the model as soon as you orbit). `applyCamera` and all presets force `(0,0,1)`.
- `load` is reassigned to refresh dimensions/selection after each reload; labels are DOM elements projected every frame and hidden when off-screen/behind the camera; the toolbar has `z-index: 5`.
- Lighting that looked right: `HemisphereLight(0xffffff, 0xb4b8c0, 2.4)` + `DirectionalLight(0xffffff, 2.2)` with `shadow.bias=-0.0005`, `shadow.normalBias=0.6` (without them the surfaces show a moiré of shadow acne).
- Colours: `new THREE.Color(r/255, g/255, b/255).convertSRGBToLinear()`.
- The Interior preset and `Top` preset use a tiny offset for Top (`[0,-0.001,1]`) to avoid the Z-up gimbal degeneracy.
